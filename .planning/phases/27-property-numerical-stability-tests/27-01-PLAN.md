<objective>
Lock the cross-cutting statistical invariants across the whole model/statistic matrix
and harden the sensitive numeric paths against precision, overflow, and conditioning
failures -- as an ADDITIVE layer on top of the Phase 26 audited, golden-pinned base.
Invariant tests assert identities that must hold for any correct implementation
(CAR == cumsum(AR), boundary/degenerate windows, monotonic window growth, cross-method
consistency). Numerical-stability guards protect matrix conditioning, bootstrap
degeneracy, long-window CAR cumulation, and GARCH non-convergence, each conforming to
the established degenerate-input contract (NA + exactly one warning in lenient mode,
error in strict mode).

Purpose: A cross-cutting bug that no single golden pin would catch (an identity broken
across the matrix, or a silently-wrong number on an ill-conditioned/overflowing path)
can never pass. This is the durable regression net that stops the recurring audit-round
bug churn, without changing any valid-input result.

Output:
- tests/testthat/helper-invariant-data.R (model/statistic registry + deterministic
  boundary/degenerate/long-window fixtures)
- tests/testthat/test_invariants.R (registry-driven universal + representative-subset
  invariant tests)
- tests/testthat/test_numerical_stability.R (sensitive-path guard regression tests)
- Additive numerical-stability guards in R/models.R / R/models_time_varying.R /
  R/bootstrap.R / R/single_event_test_statistics.R / R/multi_event_test_statistics.R,
  each routed through the existing contract and locked by a regression test
</objective>

<discrepancy_protocol>
Applies to every task that adds a guard or asserts an invariant:

- **Genuine numerical bug** (an invariant that MUST hold algebraically fails, or a
  sensitive path returns a plausible-looking wrong number / Inf / NaN instead of NA on a
  degenerate input): FIX it in the R source. Per SC5 the fix MUST NOT change valid-input
  behavior -- it changes only the degenerate/boundary/ill-conditioned path (route the fix
  through `.handle_degenerate()` or the same NA+one-warning pattern). The fix commit MUST
  precede the commit that asserts the corrected behavior, and a regression test locking
  the corrected behavior MUST accompany the fix. Note the bug + fix in the SUMMARY.
- **Correct-but-surprising behavior** (the number is right; only a naive expectation was
  wrong): fix the TEST expectation, document why inline, do NOT touch the R source.
- When unsure which bucket a discrepancy falls in, prefer NOT changing valid-input
  behavior (document + flag in SUMMARY for the plan-checker) -- an unnecessary source
  change is the higher-risk error under SC5.
</discrepancy_protocol>
