<objective>
Audit every return model (13+) and test statistic (8+) against its published academic
formula, document each convention choice (return type, forecast-error correction,
degrees of freedom, p-value sidedness, Patell denominator, and any other choice that
moves the number) in a new CRAN-shipped vignette with published-source citations, fix
any genuine formula error found (fix precedes the golden pin, locked with a regression
test), and pin the key statistics to reference constants in a golden-value test file.

Purpose: A wrong number can never silently pass, and a correct number can never be
falsely failed by a convention mismatch. This is the correctness spine of the v0.66.0
CRAN-resubmission milestone.

Output:
- vignettes/statistical-conventions.Rmd (durable convention reference, CRAN-shipped)
- tests/testthat/test_golden_values.R (published-first golden-value regression net)
- tests/testthat/helper-golden-data.R (deterministic fixtures for golden tests)
- data-raw/derive-golden-values.R (non-shipped, .Rbuildignore'd estudy2 derivation)
- Any formula fix in R/models.R / R/models_time_varying.R /
  R/single_event_test_statistics.R / R/multi_event_test_statistics.R, each locked
  by a regression test
</objective>

<discrepancy_protocol>
Applies to every audit task (per CONTEXT.md locked decision "Fix genuine errors;
document defensible conventions"):

- **Genuine formula error** (the code computes something no published convention
  supports): FIX it in the R source. The fix commit MUST precede the commit that
  pins that statistic's golden value, and a regression test locking the corrected
  number MUST accompany the fix (success criterion 2). Note the error + fix in the
  vignette's audit log and in the SUMMARY.
- **Defensible convention difference** (the code matches a published convention that
  merely differs from another implementation, e.g. log-vs-simple return, df = m-2 vs
  m-1, one- vs two-sided p): DOCUMENT it as the chosen convention with its citation
  in the vignette. DO NOT change behavior (success criterion 5 — valid-input behavior
  is frozen).
- When unsure which bucket a discrepancy falls in, treat it as a convention (document,
  do not change) and flag it explicitly in the SUMMARY for the plan-checker — changing
  valid-input behavior is the higher-risk error.
</discrepancy_protocol>
