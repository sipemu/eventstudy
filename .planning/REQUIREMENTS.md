# Requirements: EventStudy v0.64.0 — Automated AI Reporting

**Defined:** 2026-09-07
**Milestone:** v0.64.0
**Core Value:** Trustworthy numbers, trustworthy interpretation — the pipeline is never silently wrong, and the AI report cites only package-computed diagnostics, never fabricating a result.

## v1 Requirements

Requirements for the v0.64.0 milestone. Each maps to a roadmap phase.

### Report Orchestration (REPORT)

- [ ] **REPORT-01**: User can call a single entry point `es_report()` on a fitted `EventStudyTask` that harvests diagnostics (`es_diagnostics()`), assembles narrative (`es_advise()`), renders the report, and returns the output file path(s)
- [ ] **REPORT-02**: User can produce a report as part of a standard run via `run_event_study(..., report = TRUE)` (additive; defaults to `FALSE`, no behavior change when omitted)
- [x] **REPORT-03**: `generate_report()` gains a `narrative = NULL` parameter it uses as the lower-level renderer, and its existing `narrative = NULL` / `advice = NULL` output stays byte-identical (backward compatible)
- [ ] **REPORT-04**: `es_report()` deep-clones the task before rendering so the caller's `EventStudyTask` object is never mutated

### Grounded AI Narrative (NARR)

- [ ] **NARR-01**: Report narrative is assembled section-by-section, each section an independent grounded `es_advise()` request (LLM contacted once per section, independent of output-format count)
- [ ] **NARR-02**: The narrative covers executive summary, data/methods, results interpretation, and robustness/caveats
- [ ] **NARR-03**: References are pulled from the knowledge-base citation records, never generated by the LLM
- [ ] **NARR-04**: Significance language ("strongly significant" … "not statistically significant") is set by a static calibration function from p-values — the LLM is told the label, never asked to infer it
- [ ] **NARR-05**: The joint-hypothesis caveat (abnormal-return significance jointly tests the event and the return model) is included as fixed static text in every report

### Grounding Hardening (GROUND)

- [ ] **GROUND-01**: The grounding guard scans narrative prose for numeric literals absent from `es_diagnostics()` (within tolerance), extending coverage beyond the existing structured `evidence[]` arrays
- [ ] **GROUND-02**: A grounding failure degrades safely — the offending section is dropped or flagged with one warning; an unverified number is never emitted silently into the rendered report
- [ ] **GROUND-03**: Regression tests lock the report-path grounding invariant (a fabricated number in prose is caught, not rendered)

### Offline-First Fallback (OFFLINE)

- [x] **OFFLINE-01**: With no LLM provider configured, `es_report()` still renders a complete report, using the rule-based offline advice engine for the narrative (the current `report_writing`-is-LLM-only gap is resolved)
- [ ] **OFFLINE-02**: The report visibly distinguishes AI-grounded from offline rule-based narrative (section label/heading + a console message on the mode used), so rule-based output is never mistaken for AI interpretation

### Multi-Format Output (FORMAT)

- [ ] **FORMAT-01**: `es_report()` renders to HTML (default), PDF, Word (.docx), and Markdown, selectable per call (one format or several)
- [ ] **FORMAT-02**: Missing optional toolchains degrade gracefully — PDF/Word/Markdown each skip with one informative message and continue; only total inability to render the HTML baseline errors
- [ ] **FORMAT-03**: Plots switch to static ggplot2 for non-HTML formats via `knitr::is_html_output()`; interactive plotly is used only in HTML
- [ ] **FORMAT-04**: Narrative prose is sanitised per output format (LaTeX/XML special characters, smart quotes, em-dashes) so PDF and Word render without corruption

### Report Template (TMPL)

- [ ] **TMPL-01**: One fixed report template (executive summary · data/methods · results · diagnostics · robustness/caveats · references), with section presence toggled by arguments and no custom templating
- [ ] **TMPL-02**: Data/methods and results content (event/estimation windows, model, AR/CAR/AAR/CAAR tables, significance) is auto-filled from task metadata and `es_diagnostics()` keys, not from the LLM

### CRAN & Testing Hygiene (CRAN)

- [ ] **CRAN-01**: New dependencies (`tinytex`) stay in `Suggests`, `requireNamespace()`-guarded; no new `R CMD check --as-cran` NOTEs/WARNINGs vs the current baseline; the existing test suite stays green
- [ ] **CRAN-02**: All `render()` calls are `\dontrun{}` in examples and `skip_on_cran()` / `skip_if_not_installed()` in tests; `R CMD check` triggers no network access or LaTeX toolchain

## Future Requirements

Deferred to a later release. Tracked but not in this roadmap.

### Customization (RPTC)

- **RPTC-01**: User-supplied custom RMarkdown templates with pipeline-filled placeholders

## Out of Scope

Explicitly excluded this milestone. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| `officedown`/`officer` Word backend | Plain `rmarkdown::word_document()` renders clean .docx via pandoc with zero new transitive deps; rich Word features not needed for a statistical report (CRAN discipline) |
| Custom / user-supplied report templates | Fixed sensible template delivers the one-call value; custom templating is deferred surface area (RPTC-01) |
| Panel / intraday / synthetic-control report support | Those diagnostics surfaces are themselves deferred (SURF-01/02); v0.64.0 targets the single/multi-event happy path (RPTX-01) |
| Bootstrap-CI in the report | Modest extra scope kept out to ship a focused report path (RPTX-02) |
| New statistical methods, models, or estimators | v0.64.0 is reporting only; no change to statistical intent or valid-input behavior |
| Changing `generate_report()`'s existing output on the NULL path | Backward compatibility — the wrapper is additive |
| Heavy per-provider LLM SDKs | HTTP-only via the existing `httr2` client stays the single provider seam |
