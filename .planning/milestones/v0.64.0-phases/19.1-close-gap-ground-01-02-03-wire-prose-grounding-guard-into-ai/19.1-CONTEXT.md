# Phase 19.1: Close Gap GROUND-01/02/03 — Wire Prose Grounding Guard into AI Report Path

**Gathered:** 2026-09-07
**Status:** Ready for planning (gap closure — inserted after milestone audit)

<domain>
## Phase Boundary

Gap-closure phase inserted after the v0.64.0 milestone audit
(`.planning/v0.64.0-MILESTONE-AUDIT.md`) found GROUND-01/02/03 **unsatisfied at the
integration level**: Phase 17 built the free-text prose grounding scanner
`.scan_prose_grounding()` (and unit-tested it), but Phase 18's narrative assembler
never wired it into the report path. In the AI path (`provider` set) the LLM's
free-text `interpretation` prose renders into the report verbatim, so a fabricated
numeric literal is NOT caught — violating GROUND-03 ("a fabricated number in prose
is caught, not rendered") and the milestone Core Value.

This phase wires the existing scanner into `assemble_report_narrative()` and locks
the **report-path** invariant with a regression test that drives a fabricated number
through the assembler / `es_report()` and asserts it never reaches the rendered prose.

Out of scope: any change to the scanner internals (already built + tested in Phase
17), the offline path (safe by construction), or any public API.
</domain>

<decisions>
## Implementation Decisions

- **Reuse the Phase 17 scanner unchanged.** `.scan_prose_grounding(prose_fields, diag)`
  (R/advise.R:487) returns `list(sections = <named list, dropped -> "">, n_dropped = <int>)`
  and emits exactly one warning when any section is dropped. Same package namespace —
  callable directly from `R/report_narrative.R` (no `:::`).
- **Wire point:** in `assemble_report_narrative()` (R/report_narrative.R:174-195), after
  `llm_prose <- .extract_llm_section_prose(advice)` and BEFORE the acceptance check at
  line 187. Scan the single section; if `n_dropped > 0`, set `llm_prose <- NULL` so the
  EXISTING per-section offline fallback (lines 191-195) takes over. This preserves the
  drop-and-keep + single-warning discipline with no new control flow.
- **Preserve NARR-01 budget:** the scan runs on the already-returned prose; it adds no
  extra `es_advise()`/provider call. One LLM call per section is unchanged.
- **Lock the report-path invariant (GROUND-03):** add a regression test that injects a
  fabricated literal via a mock provider through `assemble_report_narrative()` (and ideally
  end-to-end via `es_report()`), asserting (a) the fabricated number is absent from the
  assembled `results`/`exec_summary`/`robustness` prose, (b) the section fell back to
  offline, (c) exactly one warning was emitted.
- **No version bump.** DESCRIPTION stays 0.64.0 (gap closure within the milestone). A NEWS
  line under the existing 0.64.0 section noting the grounding guard now covers report prose
  is optional/discretionary.
- **CRAN discipline:** ASCII-only; the new test is a fast unit test (mock provider, no
  network, no render) so it need not be `skip_on_cran()` unless it touches rendering.
</decisions>

<specifics>
## Specific Ideas

- The report-path invariant (GROUND-03) is a concrete, testable assertion:
  mock provider returns `interpretation` prose containing "99.99" (a value absent from
  `es_diagnostics()`); after `assemble_report_narrative(diag, provider = mock)`, the
  `results` prose must NOT contain "99.99" and `section_sources$results` must be "offline".
- Verify the fix does not regress the happy path: grounded LLM prose (numbers that DO match
  diagnostics within tolerance) is still accepted as "ai".
</specifics>
