## Summary

Phase 23 is a bounded surface-polish over the existing EventStudy codebase, in four areas: (1) add `format.*` for the six classes that have `print.*` but no `format.*` and refactor each `print.*` to `cat(format(x), sep="\n"); invisible(x)`; (2) selectively migrate high-value user-facing argument-validation `stop()`/`warning()` sites to classed `rlang::abort()`/`rlang::warn()`; (3) apply a consistent arg-in-backticks + value message convention on those migrated sites; (4) route informational `message()` chatter through a `.inform(msg, verbose)` helper, and a documented no-op deprecation audit. All valid-input output stays byte-identical, snapshot-locked.

The codebase is well-suited to this refactor. Five of the six `print.*` already end in `invisible(x)`; all are `cat()`-driven line-by-line, so extraction into a `format.*` character-vector is mechanical — **except `print.es_cross_sectional`**, which calls `base::print.data.frame()` on a rounded coefficient matrix (does not map to a simple line vector; needs `utils::capture.output(...)` to capture those lines). `rlang` is confirmed in Imports (DESCRIPTION:41); `cli` and `lifecycle` are confirmed absent. No `rlang::abort`/`rlang::warn` exists anywhere yet — this phase introduces classed conditions for the first time. No `_snaps/` snapshot content exists yet (dir present but empty).

**Primary recommendation:** Sequence snapshot-capture FIRST (6 print methods + 4 prose-sanitiser variants), then refactor print→format, then migrate ~15 classed-condition sites, then wire `.inform()`. gridExtra is UNGUARDED at plotting.R:348 — flag as a small in-scope guard fix (it touches the guard surface). ## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Classed conditions | custom `structure(class=…)` + `stop(cond)` | `rlang::abort(msg, class=…)` | already an Import; suppresses call by default; standard `rlang::cnd_signal` semantics; testable with `expect_error(class=…)` |
| Capturing a data.frame print as lines | manual column formatting | `utils::capture.output(base::print.data.frame(...))` | reproduces exact bytes for `print.es_cross_sectional` format extraction |
| Capturing footer side-effect | inline the footer logic | `utils::capture.output(.advisor_pro_footer())` | keeps `format.*` pure without duplicating footer wording |
| Byte-identity proof | manual string compare | testthat 3e `expect_snapshot()` | auto-manages `_snaps/`; is the sanctioned regression net |
| verbose gating | scatter `if(verbose) message()` | one `.inform(msg, verbose)` helper | single choke point; warnings/errors provably bypass it |

## Common Pitfalls

### Pitfall 1: Trailing-newline drift in print→format refactor
**What goes wrong:** `cat("Foo\n")` then `cat("\n")` vs `cat(format(x), sep="\n")` differ in the final newline and in how blank lines render.
**How to avoid:** snapshot `print(x)` BEFORE refactor; make `format()` return the exact line vector (including `""` for blank lines); verify the snapshot passes after. The `sep="\n"` join omits a trailing newline — if the original had a trailing blank line, add a trailing `""` element.
**Warning signs:** snapshot diff showing a missing/extra blank line at EOF.

### Pitfall 2: `.advisor_pro_footer()` side-effect double-emits
**What goes wrong:** if `format.Advice` both captures the footer AND the refactored `print` calls the footer again, the footer prints twice.
**How to avoid:** move the footer emission entirely into `format.*` (via capture.output), and let `print.*` be ONLY `cat(format(x), sep="\n"); invisible(x)` — do not call the footer again in print.

### Pitfall 3: Gating a warning by mistake
**What goes wrong:** routing a `warning()` through `.inform` or gating the locked one-warning paths violates the degenerate contract.
**How to avoid:** `.inform` wraps `message()` only. Explicitly exclude `.handle_degenerate` / `.validate_grounding`. Add a test asserting `verbose=FALSE` still emits the degenerate warning.

### Pitfall 4: rlang::abort message-byte change breaks existing expect_error tests
**What goes wrong:** existing tests may `expect_error(..., "Request file missing columns")` — reworded message breaks them.
**How to avoid:** grep existing tests for the exact substrings of each migrated message before rewording; update those assertions in the same task. Keep message parity (extend, don't replace, wording).
