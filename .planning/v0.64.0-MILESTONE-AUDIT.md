## Summary

19 of 22 requirements are satisfied end-to-end. The report orchestration
(REPORT-01..04), grounded narrative assembly (NARR-01..05), offline-first
fallback (OFFLINE-01/02), multi-format output (FORMAT-01..04), fixed template
(TMPL-01/02), and CRAN hygiene (CRAN-01/02) are all wired and verified, and all
four end-to-end flows (offline report, AI report, `run_event_study(report=TRUE)`,
`report=FALSE` isolation) trace cleanly through the phase seams.

**One critical gap blocks a clean pass:** the free-text prose grounding guard
(GROUND-01/02/03), built in Phase 17, was never wired into the Phase 18 report
narrative assembler. In the AI path a fabricated number in LLM interpretation
prose renders into the report unchecked — the exact failure the milestone's Core
Value promises never happens ("the AI report cites only package-computed
diagnostics, never fabricating a result").

## Critical Gap Detail — GROUND-01/02/03

**Root cause:** `assemble_report_narrative()` (R/report_narrative.R:174–195) accepts
the LLM's `advice$interpretation` free-text (via `.extract_llm_section_prose()`,
line 182) and writes it straight into `prose[[key]]` (line 189). The only guard
that runs on the AI path is `.validate_grounding()` (advise.R:220–323), which
validates `recommendations`/`evidence[]` arrays — **not** free-text prose.
`.scan_prose_grounding()` (the free-text literal scanner) is never invoked.

**Impact:** AI-path only. Offline default (`provider = NULL`) is safe by
construction (prose built from diag values via sprintf). But with a provider,
a hallucinated statistic in prose reaches the rendered report silently.

**Remediation (small, scanner already exists + tested):**
1. In `assemble_report_narrative()`, after the LLM prose is extracted and before
   acceptance (around line 187), run `.scan_prose_grounding(list(<key> = llm_prose), diagnostics)`;
   if the section is dropped (`n_dropped > 0`), set `llm_prose <- NULL` so the
   existing per-section offline fallback (lines 191–195) takes over. This reuses
   the Phase 17 drop-and-keep + single-warning machinery unchanged.
2. Add a report-path regression test (GROUND-03): inject a fabricated literal via
   a mock provider through `assemble_report_narrative()` / `es_report()` and assert
   the fabricated number is absent from the assembled/rendered prose and the
   section fell back to offline with exactly one warning.

Estimated: ~10–15 lines in one function + one regression test file. No API change,
no new dependency, offline path unchanged.
